# v0.13 五轮实现、审查与修正

本轮仍是同一 ExampleLoom 项目的维护。主代理实现，正确性代理逐轮只读审查并独立复现，研究代理核对成熟系统的能力和语义。五轮均有实际功能和回归测试，不以空提交凑次数。审核未发现阻断问题不等于形式化证明、比赛初审通过或生产采用保证。

## 五轮闭环

| 轮次 | 实质交付 | 审核发现及修正 | 验证 |
| --- | --- | --- | --- |
| 1 | 多键 inner/left/full/semi/anti 连接；关系基数约束、空键策略和匹配状态 | semi/anti 无需枚举重复键的笛卡尔积，已移除；输入及输出表头计入预算，空表头越界也立即拒绝 | 500组独立嵌套循环参考；2万重复键回归，代理独立运行约78ms（单次观察，非性能保证） |
| 2 | 按列名 strict/union/intersection 合表，保留来源 | 来源列不能覆盖任何输入同名字段，即使该列会被交集模式移除 | 250组独立按名参考；列重排、缺列、空表、重名及显式丢列策略 |
| 3 | 精确普通十进制 sum/min/max；从多批训练学习小数聚合 | 大量指标的输出改为逐项预算检查；小数证据从全部训练批次收集，修复训练顺序影响 | 350组 Python Decimal 精度1024、Inexact陷阱对照；代理另以BigInt整数尺度独立验证300组；超Int64、256位进位及3千组×63指标限额 |
| 4 | API、CLI及浏览器确认式执行：明确选择或本批全部保留候选成功一致 | 共识结果生成后清除旧的可保存管道选择，防止结果A和手写程序X错配 | 分歧/失败阻止导出；迟到响应失效；先手写不同程序的真实浏览器回归 |
| 5 | 可移植多源任务格式、任务工作台、CLI及三个完整场景 | 忙碌时禁用源文件选择器，文本编辑仍使结果失效；输出用拥有归属的同目录临时文件写入再重命名 | DAG引用、Normalize/Preserve首步语义、中间膨胀与驻留总量；API/CLI/Worker保存重载、取消重试、重复主键和文件写入失败 |

## 真实覆盖范围及成熟系统比较

项目现有单表能力包括条件表达式、有限扩展正则、宽长表转换、变长记录整理、排序、分组、整表展平和多批样例学习。本轮补齐多源执行及小数汇总，覆盖从单张表整理到多张表对齐、主数据补全、结算和对账的流程。它仍是有界转换与合成工具；不以实现所有 Polars、pandas 或 PROSE 功能作为“通用”的定义。

| 一手参考 | 借鉴与本轮区别 |
| --- | --- |
| [pandas merge](https://pandas.pydata.org/docs/reference/api/pandas.merge.html)（[BSD-3-Clause](https://github.com/pandas-dev/pandas/blob/main/LICENSE)） | 参考关系基数校验、匹配来源和稳定顺序；独立实现字符串多键哈希连接。我们的空字符串策略不是 pandas 的 null 匹配体系；没有复制其代码或自动学习连接 |
| [Polars concat](https://docs.pola.rs/api/python/stable/reference/api/polars.concat.html)（[MIT](https://github.com/pola-rs/polars/blob/main/LICENSE)） | 参考按名纵向对齐；我们的缺列补字符串，明确保留来源，不具有 Polars 的类型提升和 null 体系 |
| [Python decimal](https://docs.python.org/3/library/decimal.html) | 只用于独立测试参考；运行时是 MoonBit 逐位带符号加减和精确比较，不依赖 Python、Double 或 Int64 缩放 |
| [PROSE Interactivity](https://www.microsoft.com/en-us/research/project/prose-framework/interactivity/) | 保留用户选择和补样；有限候选在一个批次一致不表示未知数据正确，不输出正确概率 |

以上为公开语义参考，不是算法首创声明。此前 vendored 正则及数据来源声明继续适用。尚未实现 SQL、流式执行、数据库连接、自动学习多源连接、任意正则/PCRE 全兼容、完整小数运算上下文、除法与平均值。

## 三个可运行的完整多源场景

| 使用者与问题 | 输入、操作 | 输出和验证 |
| --- | --- | --- |
| 商家把订单关联商品分类 | orders按SKU+仓库连接catalog；右键默认唯一；按分类及匹配状态汇总小数金额 | 食品0.3、图书1.25，未知商品2.5保留left_only；重复主键报错，不静默取第一条 |
| 供应商跨月结算 | 两个月列顺序不同，第二月多备注列；显式union按名合表并加月份来源，再按供应商/币种汇总 | S1/CNY=0.3，S2/USD=9007199254740993，精确保留超过双精度精确整数范围的金额及小数调整；此示例未超过Int64 |
| 仓储库存与目录对账 | 库存与目录full join，空键默认不匹配；后续选列重排 | 两侧遗漏记录均保留；both、left_only、right_only区分匹配情况，空键不错误合并 |

完整源CSV、任务和独立预期输出位于 [examples/jobs](../examples/jobs/)。这些是构造工作流，不是客户采用证明或外部盲测。运行：

```sh
moon check --deny-warn --target all
moon test --deny-warn --target js
node scripts/build.mjs
node scripts/data-job-test.mjs
node scripts/serve.mjs
```

打开 `/jobs.html` 选择案例，替换各张源表，运行、核对、下载CSV或保存任务。任务规则不包含源文件数据。CLI可运行测试生成的独立文件：

```sh
node bin/exampleloom.mjs run-job --job artifacts/jobs/product-enrichment-saved.json --sources artifacts/jobs/product-enrichment-files.json --out artifacts/jobs/result.csv
```

自有任务：工作台下载规则作为task.json；files.json使用 `[{"name":"orders","file":"orders.csv"},{"name":"catalog","file":"catalog.csv"}]`，文件路径相对files.json所在目录。先 `validate-job --job task.json --out checked.json`，再 `run-job --job checked.json --sources files.json --out result.csv`；命令均以 `node bin/exampleloom.mjs` 开头。

## 协议、确定性及边界

`join_tables(left,right,spec)` / JSON `join_tables`：1–8对字符串精确相等键，不隐式trim、转换数字或大小写。默认 `kind=left`、`relationship=many_to_one`、`empty_keys=never`、`right_suffix=_right`、`missing_value=""`、`indicator=_match`。关系还支持one_to_one/one_to_many/many_to_many，空键可显式match。唯一性只约束当前空键策略下可参与匹配的键，包含未实际匹配的有效键。非唯一连接必须明确允许；复合键用JSON数组编码。按左行和右匹配原序输出，full最后追加右侧未匹配行。右键不重复输出；full将右键按对应位置填入左键列。强制状态列区分补空与真实空值；后缀二次冲突及状态列冲突均拒绝。

`concat_tables(sources,spec)`：1–8个名称唯一的NamedTable。默认strict要求相同列集合但允许重排；union保留按首次出现的列并集；intersection是用户明确同意取交集，无共同列时报错。表、行原序保留，无去重或类型转换。默认缺列补`""`，来源列`_source`，来源列不能与任何输入列重名。

连接/合表输入合计上限200000 cells、2000000 UTF-16单位（含表头）；单表仍受20000行、64列限制。结果先检查行数膨胀，再逐值计输出文本。超限报错，无部分表返回。空字符串不等同SQL NULL。

`GroupMetric`新增 SumDecimal/MinDecimal/MaxDecimal，对应aggregate JSON指标 `sum_decimal/min_decimal/max_decimal`。输入为1–256 ASCII字符的普通带符号十进制，拒绝空、空格、指数、分隔符、NaN和不完整小数。sum用最多1024位系数的精确逐位加减；结果为无多余前导/尾随零的普通十进制，负零统一0，min/max也输出规范值。空的全局分组返回空聚合值和count0；无键空表不伪造数值0。原Int64指标及其溢出报错保留。仅当训练实际出现小数或超Int64数值时才扩展相应学习候选，重放所有训练；不看测试答案。

`execute_table_candidates(...,chosen?)` / JSON `execute_table`：明确零基chosen时只执行该选择；未选择时所有保留候选必须对完整本批执行成功且结果完全相同。返回explicit_choice或observed_consensus，后者chosen为null，不自动把某个程序标为正确。显式路径受200k cells/2m文本限制；一致性比较沿用2000行/20000 cells/250k文本限额，超限拒绝而非采样。只有1个保留候选同样不证明候选完整、未截断或未来数据正确。CLI `execute-table --data ... --report ... [--choose N] --out ...` 遵守相同行为。

DataJob v1含sources、stages、output。1–8源、1–8阶段，名称全局唯一，只引用已存在节点，output必须是末阶段。阶段为显式join/concat/transform；全部静态校验后才执行，JSON未知字段和未来引用拒绝。格式不含可执行代码或隐式I/O，文件读取在CLI/浏览器适配层处理。首步NormalizeLayouts和PreserveExtraColumns与原管道一致。每步临时表和所有驻留输入/阶段输出均受限额；保留中间表，**不是流式或无限内存DAG执行器**。CSV只在整任务成功后返回。

CLI使用同目录独占创建的临时文件，完成写入/关闭后rename；只有取得归属的文件才清理。验证或rename失败不覆盖已有目标；这不承诺磁盘fsync持久性或任意断电恢复。

## 原始外部基准没有改成100%

仍保留全部250道原Foofah任务、25个缺测试答案标记及225分母。默认自动首候选198/225、事后候选上界211/225；新功能不以改变参考或排除失败提高成绩。13道歧义题的额外意图/补样实验仍单独报告，不能加进自动成绩。

例如训练 `[[A]]→[[A]]` 同时符合恒等和整表展平；下一批两行的正确意图不能由单例唯一决定。我们可以增加能力、展示分歧和接受更多独立监督，但不能据此保证原始自动题全部通过、所有未知数据正确或季度获奖。[原27题逐类审计](V012.md#27题审计和评价口径)保留。

最终构建、测试、CI与发行证据在 [evidence](evidence/) 和 [Actions](https://github.com/zhangbowen2006/ExampleLoom/actions)。公开源代码及测试可逐项复现，不能用“100%单元测试通过”替代“外部任务100%正确”。

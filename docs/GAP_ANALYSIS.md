## 本轮为何选择排序

目录、对账明细、按读数排列的长表都需要可复用的行序。此前管道只能沿算子自身规定的顺序输出，无法表达“地区升序、金额降序”这类独立规则。新增 `SortRows` 既可显式使用，也可从示范输入/目标自动推导；可与 Unpivot 等已有操作组合，仍在同一 MoonBit 核心、浏览器 Worker 和 CLI 中执行。

执行语义包括 1–8 个排序键、各键独立方向、Unicode 标量文本序、精确普通十进制数值序、全等时稳定保序、原始单元格拼写保留及有位置的错误。数值不经过浮点或 Int64 缩放，因此在支持的 256 字符输入范围内不会因表示方式丢失比较精度。数字语法不包括指数、分组符或隐式空值转换。

学习器只考虑训练表的完整行置换，按重复行出现次数追踪原始位置，利用前缀等值组内的目标单调性和稳定次序产生排序键。学习至多三个键，限制 32 个前缀、每状态两个排序见证，并将重放计入既有预算；这样控制新增候选对原有结构候选的挤占。信息不足时保留有限候选，依靠新批次比较与本人补充正确示范消歧。

## 已验证与未验证

- 14 项新核心回归使总数达到 122；覆盖负数、负零、不同小数长度、超过 Int64 的值、Unicode 字典序、重复键、稳定性、八键边界、全部训练对、三键学习与结构组合。
- 128 组参考由独立 Python `Decimal` 和稳定排序产生，未导入本项目解析/比较代码。三个业务流程包括新批次、按列名重绑定、保存重载与真实浏览器下载。[记录](evidence/sorting-v0.7.0.json)
- 完整外部任务对照没有提高首候选成绩，也没有回退。Foofah 与 SyGuS 已用于开发；没有运行这些成熟系统的同机速度横评，也没有客户部署证据。[基准及限制](BENCHMARKS.md)

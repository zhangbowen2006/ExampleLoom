# v0.15：从示例学习连接、筛选和汇总

## 解决的问题与实际范围

订单与商品目录关联后，经常还需筛选已支付记录，再按类别汇总。v0.14 的连接学习只能提出一次选列、汇总或排序；遇到需要先筛选的任务没有对应的搜索路径。v0.15 增加“等值连接 → 单个条件筛选 → 汇总”这一受限组合，在已有 MoonBit 核心、库、CLI 和浏览器工作台中运行。

新案例 [paid-orders.json](../examples/join-learning/paid-orders.json) 使用两批输入及目标表演示业务规则。系统学习连接SKU、筛选`status == "paid"`及分组求和；另一批订单中的待支付和取消记录不计入，得到 toy=5、media=1250。金额以整数分表示。已有两个双键和小数汇总场景继续可运行。三个案例均为构造流程，没有声称客户采用。

## 搜索语义与限额

- 筛选候选只使用训练源表中的字符串常量，尝试等于或不等于一个值。每列在全部训练批次最多8种不同值，超过时跳过并报告`truncated`。不做隐式大小写、去空格、数值阈值、任意布尔组合或正则条件推导。
- 每个连接假设最多32次筛选尝试，整个请求共享2048次；`filter_evaluations`报告实际次数。既有`max_evaluations`仍限制连接假设数，不与筛选计数混淆。连接的训练和中间结果限额继续适用。
- 先尝试原有直接变换，再尝试筛选与汇总。每个连接假设最多保留一个下游解，候选排名仍是语法偏好，不是正确率。即使`truncated=false`也不表示已枚举任意程序或所有下游解释。
- 筛选前后都保留列名绑定；候选需在所有原始训练源表上完整重放。保存任务沿用既有DataJob v1、Pipeline v2和`filter`/`aggregate`编码。更改源表列顺序后仍按名称绑定。
- 被条件排除的非法金额不会参与求和；符合条件的非法金额会使整个任务失败。新批次仍须核对，训练拟合不保证未知数据正确。
- 同时修正此前连接学习忽略聚合及排序见证截断标记的问题，内部候选受限时会体现在最终报告中。

## 复现与证据

```sh
moon check --deny-warn --target all
moon test --deny-warn --target js
node scripts/build.mjs
node scripts/join-learning-test.mjs
python scripts/generate-join-filter-oracle.py
node scripts/join-filter-oracle-test.mjs
node scripts/serve.mjs
```

浏览器打开`/join.html`并选择“已支付订单筛选汇总”，搜索、选择、在下一批数据验证并下载CSV和任务。CLI完整训练、明确选用、保存和重放由`join-learning-test.mjs`实际执行。

SQL对照使用固定种子生成40个额外构造批次，独立运行SQLite的JOIN、WHERE和整数SUM，并按原输入首次出现顺序核对输出。覆盖空输入、未匹配键、负值、列重排、状态尾空格及被过滤的非法金额。SQL只作为测试参考，运行时无SQLite依赖。这不是独立抽样的业务集、盲测、大规模性能测试或全部任务正确性证明。

本机JS、Wasm、Wasm GC各183项MoonBit测试通过；三个学习案例与既有三个显式多源任务的API/CLI及真实浏览器流程通过，40组SQL构造对照全通过。另验证筛选后小数求和`0.1 + 0.2 = 0.3`，并保留超过Int64范围的普通十进制数。逐项运行记录：[学习流程](evidence/v0150-join-learning.json)、[浏览器](evidence/v0150-join-browser.json)、[SQL对照及额外数值检查](evidence/v0150-join-filter-oracle.json)。

已有Foofah及Auto-Tables口径保持独立；新构造案例不加到其成功数中。当前的全部自动检查及原生后端结果以[GitHub Actions](https://github.com/zhangbowen2006/ExampleLoom/actions)为准。

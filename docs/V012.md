# v0.12：多布局输入与可核验补样

本轮继续维护同一 ExampleLoom 项目，没有改名重复申报或复制其他账号项目。新增能力集中在真实输入布局变化、歧义消解和有限候选的结构覆盖；没有为外部任务添加专用题号分支，也没有修改原题、留出答案、评分或分母。以下是技术事实材料，不是参赛者独立撰写的正式申报书。

## 27题审计和评价口径

| 分类 | 题数 | 具体范围与处理 |
| --- | --- | --- |
| 意图或监督不足 | 13 | 第27、33、40组各1/2/4/5题，以及15_1；单批记录不能一般性区分整表展平、固定分组、选择/分组。保留结构候选，建议补样；默认首候选不凭留出答案调整 |
| 训练/测试参考布局差异 | 10 | 第6组的日期/商品列顺序，第29组的 sum/count 布局。记录原始差异，继续按原评分计失败；不推断任意程序均不可能满足 |
| 第34组不规则参考 | 2 | 34_1、34_2 的通常分组语义产生14列，原参考15列并额外重复字段。记录逐值证据，不加入“第三条重复 Account3”特例 |
| 未见布局或规则 | 2 | divide_1、merge_split_1 的测试输入出现训练没有的列布局。显式布局规则能处理已声明变化，不能证明从单列样例自动推断未知 schema |

`node scripts/audit-remaining.mjs` 直接读取未修改原题生成诊断；分类不是“修正后的答案”。原始自动基准仍保留全部250题，25题没有有效测试答案，成功率分母225。当前默认首候选198/225；事后检查任一候选正确的上界211/225，较0.11的209多2题，不能称为自动正确211题。保留语法家族提高替代结构覆盖，但不保证语义去重或完整覆盖，首候选仍由原成本与 JSON key 排序确定。

另行执行 `node scripts/assisted-diagnostic.mjs`：对上述13道已暴露歧义题，预先声明整表展平或 c0/c5 分组意图，使用独立 JavaScript 参考为输入变形提供标签，至多3次额外补样；结果13/13，共19对新增示例。过宽建议可被模拟使用者拒绝，改用已知训练行构造的短批次，并记录来源。原训练保留，每个候选重放所有训练，首候选固定后才读取测试参考判分。该成绩是预设意图和独立参考标签的辅助诊断，**不能与198相加、不能冒充无辅助成绩、真人验证或独立泛化盲测**。

## 接口与边界

`TableStep::NormalizeLayouts(Array[LayoutRule])` 编码为 `["normalize_layouts", rules]`。规则对象包含 `name`、`when`、`recipe`，配方和条件采用已有严格版本化编码。1–16条规则，名称唯一非空；每条最多16输入列、8输出列，所有规则输出名称和顺序必须相同。所有规则都静态校验，即使某批数据缺少它的源列。规则缺必需源列则不适用；逐行必须恰有一条命中，零条或多条、谓词/表达式错误都会整体失败。不会静默回退或输出半张表。最多200000次行×规则检查，2000000 UTF-16输出单位，并沿用表格单元格限额。

规范化只能是管道首步，不能与 PreserveExtraColumns 组合；它明确只输出所声明的 canonical 字段。此时 `Pipeline.columns` 记录首批历史输入 schema，不再作为全局必需源列；每条规则按自己的 `recipe.columns` 绑定。其他旧管道保持既有 schema 行为。

`synthesize_table_with_layouts(examples, rules, ...)` 对所有原始训练执行显式前缀，只学习规范化之后的程序；depth/state/evaluation预算预留前缀开销。纯规范化目标可在1步、1状态、1评估内成功；不足预算返回 truncated，非法配置、目标和规则仍拒绝。学习后再重放每一对原始输入输出。规则本身**不是从样例学得**。JSON `synthesize_table` 可选 `layouts`；旧请求不变。CLI：

```sh
node bin/exampleloom.mjs learn-table --pairs batches.json --layouts layouts.json --out report.json
node bin/exampleloom.mjs pipeline --report report.json --choose 0 --out pipeline.json
node bin/exampleloom.mjs transform --data next.csv --pipeline pipeline.json --out result.csv
node bin/exampleloom.mjs probe-table --data training.csv --report report.json --out suggestion.json
```

`propose_table_input(pipelines, inputs)` / JSON同名操作接收1–8候选和1–8源表，源表1–128行、1–16列。API不能自行证明调用者源表来自训练集；内置UI和诊断只从训练数据构造。按源表顺序尝试重复整批行、反序、删首行、删末行和取首行，完整去重，合计最多8次比较，前序源表可能耗尽预算。比较超限记 skipped；全部失败和一致结果不作为建议。至少一个成功候选的分歧才可建议；执行错误不代表任何预测正确。

返回 `source_index`（零起）、`mutation`、输入表/CSV、候选分组及 `n²−Σ组大小²` 分歧分数，不包含正确标签。分数只是本次有限探针内的排序，不能解释为置信度、全局信息最优或业务有效性。无建议也不证明普遍等价。网页明确标记“构造的补样输入，可跳过”，补充训练仅复制输入、目标留空；训练、意图或规则编辑会使迟到建议失效。

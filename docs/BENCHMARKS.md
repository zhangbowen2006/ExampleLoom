# v0.4 外部任务与旧版对照（2026-11-10）

完整保留 Foofah 上游 250 个 exp0 任务（50 个任务族），固定源码版本与 MIT 许可见 [来源说明](../fixtures/foofah/README.md)。没有按成功与否筛选数据。任务参与过本轮开发，不是盲测，也不能作为一般生产准确率。

## 修正测试答案口径

v0.3 报告把 25 个写着 `NOT AVAILABLE, SORRY` 的占位测试答案当作失败。此次把它们明确列为“无测试答案”，仍保留在全部 250 个任务和训练统计中；225 个有实际答案的任务用于计算测试成功率。旧版与新版都按同一新口径重跑，旧版成功数仍为 105。不是只修改新版分母来提高成绩。

缺答案任务来自任务族 3、18、24、28、41，完整清单在 [数据审计](evidence/benchmark-data-audit.json)。没有发现完全相同输入却有不同参考输出的直接矛盾。5 个输入列数超限任务均属于缺答案的任务族 41；保留在总表，不冒充 225 个可评估任务中的失败。

## 同机三轮交替对照

使用不可变的公开 v0.3.0 引擎（SHA-256 `8085e8ebfd6692d6bb2dc193eebb584c9302c90e3246ca54e9316e40005703c1`）和当前引擎，每个版本运行 3 轮，按旧→新、新→旧、旧→新交替顺序执行。相同机器、解释器、5000ms 单任务壁钟上限及参数：4 步、128 个总保留状态、2000 原始算子预算、8 候选。三轮每个任务的训练/测试结果一致。

| 指标 | v0.3.0 | v0.4.0 |
| --- | --- | --- |
| 完整任务清单 | 250 | 250 |
| 有实际测试答案 | 225 | 225 |
| 训练表有一致候选 / 250 | 137 | 200 |
| 首候选在有答案任务逐格一致 | 105/225（46.7%） | 150/225（66.7%） |
| 同一成功数相对全部清单 | 105/250 | 150/250 |
| 已找到候选中至少一个测试完全正确 | 117/225 | 164/225 |
| 搜索截断，包括已找到解的任务 | 240/250 | 245/250 |
| 超时 / 意外执行错误 | 0 / 0 | 0 / 0 |
| 搜索耗时 p50 | 51.4ms | 73.5ms |
| 搜索耗时 p95 | 98.7ms | 126.0ms |

净增加 45 个首候选成功任务，成功率增加 20 个百分点。新增通过 51 个、回退 6 个，均在 [完整比较记录](evidence/comparison-v0.3.0-v0.4.0.json) 中逐项保留。回退涉及转置/记录打包歧义、文本切分和单样例分组；不能只报告新增成功。

**扩大覆盖的代价是多数搜索更慢，不能宣称整体加速。**本次 p50/p95 是三轮各自分位数的中位数；统计从 MoonBit 调用开始，不含 Worker 启动、文件读取和测试表验证。机器为 Windows / i7-14650HX / Node 24.22.1，不外推其他平台、业务或吞吐量。新语法和算子工作量已变化，数值预算相同并不代表执行的工作完全相同。

“至少一个正确”是使用测试答案事后计算的 oracle 上界，不是产品的自动选择策略。首候选按训练得到的成本排名固定，TestingTable/TestAnswer 不传给学习器，也不用来挑选首候选。完整表的列名、行序、空值和前导零逐格核对；错误/超时保留在可评估分母内。上游有测试行与训练行重叠，逐任务 overlap 计数保留；50 族内部变体存在相关性。

[旧版修正后逐任务结果](evidence/benchmark-v0.3.0-corrected.json)、[新版逐任务结果](evidence/benchmark-v0.4.0.json) 包含来源文件哈希、引擎哈希、状态、训练一致性、首候选程序、测试失败和时间。原 v0.3 历史快照 [仍然保留](evidence/benchmark-v0.3.0.json)，不覆盖历史记录。

## pandas 差分验证与构造泛化检查

以 pandas 3.1.0 的 pivot、melt、groupby、ffill 和 concat 生成语义参考，共 36 个固定随机种子的成对任务，训练与测试使用不同编号和随机值。涵盖动态类别、上下文传播、标记/空行分段、带标签单元格及合并标签。72 次显式程序执行均与参考一致，36 个任务的自动学习首候选在下一批表也全部通过，见 [逐任务记录](evidence/pandas-v0.4.0.json)。

这是项目构造的差分与泛化验证，不是另一套独立外部盲测；不与 Foofah 成功数相加，不当作客户部署证据。

## 功能与实际差距

从“先找到的解”改为有成本排名的搜索，新增组合见证、共享上下文的有限正则推断、动态透视/变长记录等能力。多对训练输出现在可有不同维度，用户可提供额外样例区分转置和定长打包。核心仍为 MoonBit 独立实现，pandas 仅在验证期间调用。

仍有 75 个有答案任务的首候选未通过，搜索大量截断，没有一般完备性保证。任意列组合、数值聚合、多表连接、任意正则/替换模板及条件与结构的全面联合合成仍未覆盖。没有运行 PROSE/Foofah 本体，不能给出二者的同机数值排名。

## 复现

```sh
python scripts/import-foofah.py
node scripts/build.mjs
node scripts/benchmark.mjs
python scripts/fetch-baseline.py
node scripts/compare-benchmarks.mjs
```

首次取基线需网络；工作台归档和引擎都用固定 SHA-256 校验。比较默认 3 轮，BENCHMARK_REPEATS 可显式设置；更换次数、预算或机器需要另行标明。全部原始运行在 artifacts/comparison 中，不把最好的单轮挑出来报告。

可选差分验证（安装 pandas 3.1.0）：

```sh
python scripts/generate-oracle-cases.py
node scripts/oracle-test.mjs
```

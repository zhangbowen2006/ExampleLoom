# 功能范围与参照系统

## 当前 v0.14 系列范围

当前版本支持条件/正则与有界单表学习、显式多键连接、按名合表、精确普通十进制聚合，以及可保存多源任务。v0.14新增从多批示例学习有限两表等值连接及一步后续转换；不支持自动推导任意多源任务或完整PCRE。[连接学习范围](JOIN_LEARNING.md) · [显式多源场景](V013.md) · [当前验证](INITIAL_REVIEW.md)。以下按版本保留能力演进，不应把旧版限制或旧测试数量当作当前范围。

## v0.10：原子正则、重复键值记录与输入列保留

扩展正则支持原子组和占有量词；运行时共享限额并保留明确不支持的 PCRE 语法。[范围与验证](REGEX_PROFILE.md)

`PivotRecords` 以第一个标记键分段，输出首行字段名和多行记录；字段可随新批次增加，缺失值留空，其他重复键报错。学习器可以根据训练表生成该候选，但不同用途可能需要不同分段规则。[完整流程](../examples/structures/key-value-records.json) · [语义](PROTOCOL.md)。

管道首步 `preserve_extra_columns` 可显式保留新输入中未声明的列，旧管道默认行为不变；后续选列或重组依然可以丢弃列。该示例为手工管道。[示例](../examples/structures/preserve-columns.json)

## v0.9：变长记录、分组报表和正则补强

新增 `UpdateColumns`：表达式同时读取原始行，仅更新指定的既有列，保留先前结构步骤产生的其余列；整个步骤遇错无部分输出。学习器在动态列结构之后可提出该候选，且所有候选需重放全部训练表。表格工作台新增「变长记录整理」「分组报表整理」「联系方式整理」，包含新批次字段和行数变化。[协议和使用限制](PROTOCOL.md) · [测试](../update_columns_wbtest.mbt)

带表头的明细见证依据非空键/空值识别表头；`label:value` 见证仅保留包含示范分隔符的明细。空值、漏写分隔符或原始业务格式不符合这些假设时，用户应检查候选并补充训练，不能假定数据都被保留。推断出的固定字符切片也需要新样例验证。

正则新增有限可变宽度后向断言、忽略大小写反向引用和 `\x{...}`；部分 PCRE 语法仍未实现。[准确范围和 PCRE2 验证](REGEX_PROFILE.md)

## v0.8：正则、条件与结构组合

以 `(?rx)` 显式扩展原有正则语义：前向断言、固定标量宽度后向断言、命名捕获及替换、反向引用、通用 Unicode 类别和作用域标志。条件、配方编码、PBE 提示与结构行映射调用同一实现。原方言保留，超限报错。[详细覆盖、许可证和限制](REGEX_PROFILE.md) · [三个完整流程及独立对照](../scripts/regex-extended-test.mjs)

下文各版本章节记录当时范围；v0.5 的“前后查找、反向引用不支持”已由本轮扩展方言补齐。仍未支持任意长后向断言、PCRE 全部扩展或从少量示例生成任意正则。23 类表格操作与有限 DSL 不等于成熟系统的所有能力。

## v0.7：从样例学习稳定排序

新增第 23 类结构操作 `SortRows`，支持 1–8 个按名称绑定的排序键，各键独立选择文本/十进制及升序/降序。文本按 Unicode 标量字典序、区分大小写，不做语言区域排序。数值比较直接解析最多 256 个 ASCII 字符的普通十进制文本，不转换成浮点或缩放到 Int64；相同数值如 `01.00` 与 `+1` 保持原始顺序，所有输出单元格保留原文。

学习器仅处理训练输入的完整行置换，以重复行的出现次数匹配原始位置，再用目标在前缀等值组内的单调性、稳定次序约束推导至多三个排序键。最多保留 32 个前缀和每状态两个排序见证；新算子与现有操作共享原有搜索深度及求值预算。所有候选在全部训练表上重放。排序可与 Unpivot 组成两步程序，学习阶段不接收新批次的答案。

128 组 Python `Decimal` / 稳定排序构造对照及三个新批次流程通过：[记录](evidence/sorting-v0.7.0.json)。空值、指数记法、分组分隔符及非法数字不被数值模式隐式解释；报出行、列并停止导出。文本模式允许空字符串。科学计数法、区域化校对规则及可配置空值位置不在本轮范围。示范不足时数值序与文本序可能同样成立，应通过已有候选比较及补样流程消歧。

## v0.6.1：表格候选的比较与补样

`compare_table_candidates` 把最多八条保留管道用于同一批未标注数据，按完整列名、行序和全部单元格分组；执行错误保留为独立结果。报告前两组的首个差异，不自动调整排名、选择管道或把预测当作训练标签。全部执行失败单独返回 `all_failed`，单组成功的一致只描述有限观察。

工作台「候选歧义与补样」从一条记录开始，展示转置、打包等解释在新批次上的差异。添加训练时目标留空；使用者提供正确目标后再学习，再对第三批不同数量的记录运行。[完整数据与目标](../examples/structures/ambiguous-records.json) · [API 与外部任务验证](../scripts/table-comparison-test.mjs) · [浏览器流程](../scripts/table-comparison-browser-test.mjs)

比较使用完整批次，不截断记录。输入及每个成功输出各限 2000 行、20000 单元格、250000 UTF-16 单位；超限使比较整体失败。原有转换限额不变。两道 Foofah 原题暴露了首候选失败和可用替代结果；这项诊断不将表格首候选成功率从 179/225 改为全部通过。[本轮重放](evidence/maintenance-v0.6.1.json)

## v0.6 可复现能力

- 导入位置字段的三个样例，可只缩写第二个词并补齐缺少的状态后缀。训练中同名地点保持原样，新输入 `Other; North West` 输出 `Other; NW; LIVE`。[工作流](../examples/normalize/scenario.json)
- 时间和多个读数放在一个分隔字段时，学习拆分、Fold 和选列。新批次可有更多记录、负数和前导零。[回归用例](../search_completion_wbtest.mbt)
- 重复键值记录可学成 SplitColumn → CarryContext → PivotGrid → MapRows。新批次记录数变化时仍生成标签行和数据行。[工作流](../examples/structures/record-grid.json)
- 打包后选列的候选在全部训练对匹配目标。按观察键分组优先于固定大小打包，以减少新批次记录数变化时的误判。单行训练允许产生行映射候选，使用者仍需核对新数据。

## v0.5.1 维护修复

- 新增固定长度的分隔词前缀和后缀学习。在「姓名首字缩写」中用不同长度的姓名演示，未参与训练的 `Amina Smith` 输出 `A.S.`。Unicode 回归覆盖单字和补充平面字符。[示例](../examples/initials/scenario.json)
- 为所有输入列先尝试基本选择器，修复长字段消耗预算后其他列无法被选择的问题。输出位置搜索使用单条样例的成本下界引导，偶然从所有样例抽出同一标点的选择器仍可参与消歧，但成本高于直接字面量。用 4000 原子、30000 步的上限验证长字段拼接能得到完整字段加分隔符的程序。[核心回归](../synthesis_wbtest.mbt)
- 保存或载入管道时若训练数据变化，结果会被丢弃。重新搜索会清空旧候选，Worker 出错后的下一次操作可自动重建。四项真实浏览器回归覆盖这些过程。[延迟响应测试](../scripts/browser-recovery-test.mjs)

Foofah 在整表输入输出上搜索清洗程序。其源码提供按列拼接、填充、按固定行数重组等操作，ExampleLoom 与它在这些任务上有实质重叠。这里可核验的交付包括独立浏览器工作台、按名称绑定的 JSON 管道、结构化的正则行映射和多指标分组。两套上游系统的整机速度没有在本次环境中同机测量。[Foofah 算子源码](https://github.com/umich-dbgroup/foofah/blob/970864cd53b4c774a3dbdf4589d207f57ec63208/foofah_libs/operators.py) · [ExampleLoom 协议](PROTOCOL.md)

本项目沿用 ExampleLoom 的仓库和历史，核心搜索与运算由 MoonBit 实现。其他相邻项目及依赖来源见[项目调研](RESEARCH.md)。

## 可以复现的三个完整场景

1. 供应商运营整理混合格式编码：输入 `examples/conditional/input.csv`，前四行分别示范 local/global 的正确输出，搜索并选用条件程序，后两行得到 `CN/0777`、`INT/45001`。自动化验证训练和留出所有值，浏览器检查真实 `If` 程序。
2. 运维人员提取带噪声记录中的 ref：输入 `examples/regex/input.csv`，给两行答案与 `ref=([[:digit:]]+)` 提示，选用捕获规则，另两行得到 `70004`、`001234`，不能拿其他数字替代。API 和浏览器都要求实际首候选为 `capture`。
3. 财务运营向分析系统输出长表：按 `examples/structures/unpivot.json` 提供 A/B 宽表和目标长表，学习 Unpivot 管道，输入列重排后的 C/D 新表，得到四条月份记录，保留前导零、零值和空格。验证保存/重载、CLI 全流程、浏览器整表下载和所有输出值。

另外提供连续行打包、原始网格 Melt 的完整流程。上述业务演示为构造数据；外部任务不是这些演示的变体。尚无客户部署、用户采用或业务收益证据。


## v0.4 新增可复现流程

- `examples/structures/dynamic-pivot.json`：监测开发者把长表还原为原始网格；下一批新增 pressure 类别，按实际数据产生新列，并保留零与空单元格。
- `examples/structures/header-details.json`：运营人员把每个表头的编号与名称传播到明细；新表头替换上下文，首个表头前出现明细则报错。
- `examples/structures/labelled-grid.json`：分析人员把 low:007 等单元格还原为网格，组合 Fold → SplitColumn → PivotGrid；下一批标签变化仍可运行。

这些独立业务流程及前述场景均通过 API/CLI/真实浏览器验证；仍为构造数据，不声称客户采用。pandas 差分验证与外部 Foofah 任务分开报告。
